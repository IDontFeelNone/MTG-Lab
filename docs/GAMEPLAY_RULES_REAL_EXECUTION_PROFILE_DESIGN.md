## Projection readiness and execution readiness

`READY_FOR_RULE_PROJECTION` describes the earlier source verification and
selection boundary. It says nothing about complete state semantics, executable
primitives, exception handling or runtime approval.

Execution readiness is separate and has explicit states: `NOT_ASSESSED`,
`BLOCKED`, `PARTIALLY_READY`, `READY_FOR_EXECUTION_PROFILE_REVIEW` and
`READY_FOR_RUNTIME_IMPLEMENTATION`. A partial vocabulary/state candidate may be
useful to a future schema while remaining `execution_ready=false`. No selected
rule is marked ready to execute. The state `READY_FOR_EXECUTION` is not awarded.

Per-rule classifications are a set, not a mutually exclusive label:

| Classification | Meaning |
| --- | --- |
| `REFERENCE_ONLY` | Source authority or vocabulary with no direct executable transition |
| `STATE_MODEL_SEMANTIC` | A future representation concept, without activating behavior |
| `PRECEDENCE_SEMANTIC` | Ordering or conflict semantics requiring a complete conflict model |
| `EXECUTION_PRIMITIVE_CANDIDATE` | A possible future deterministic primitive, currently unimplemented |
| `BLOCKED_BY_DEPENDENCY` | A prerequisite is unresolved or otherwise incomplete |
| `BLOCKED_BY_EXCEPTION_SET` | A known exception family is not projected/reviewed |

## Deterministic dependency and exception closure

The original projection graph is preserved. The review walks all relevant
projected dependencies and references, including exception relationships, to a
stable fixed point. Cycles are handled as a visited set; the presence of a cycle
is not proof of closure. Thus projected `101.2a` cannot close `101.2` while
`113.10` remains unresolved, and `108.4a` inherits both ownership and control
blockers. A projected node is not automatically an execution-ready prerequisite.

`CLOSED`, `OPEN` and `UNKNOWN` are explicit closure states. The review separates
`known_dependency_closure` / `known_exception_closure` from complete semantic
`dependency_closure` / `exception_closure`. A known-metadata `CLOSED` value means
that the retained graph has no remaining known prerequisite of that kind; it
does not establish complete execution closure. Every selected rule's complete
dependency closure remains `OPEN` or `UNKNOWN`, and no selected rule has complete
`CLOSED` exception closure. `OPEN` records a known unresolved item. `UNKNOWN`
records an unmodeled area that could affect the answer. Absence of an edge in
this small graph cannot prove general semantic closure.

The unresolved source references remain exactly `104.3a`, `111.2`, `112.2`,
`113.10` and `407`. They are placeholders only. No text, anchors, paraphrases or
new projected records are created for them. The known exception families remain:

`104.3a`, and for both `101.2` and `101.2a` through their ability-modification
boundary and unresolved `113.10`. `400.2` has `UNKNOWN` exception closure for

A deterministic promotion gate denies execution if a runtime-used rule has any
unresolved dependency, an unprojected result-affecting exception, an unsupported
required primitive, an unreviewed projection, a release incompatibility, missing
verified anchor lineage or an unknown capability that could alter its result.
Exception closure is checked separately: `OPEN` or `UNKNOWN` denies promotion
whenever the missing exception could alter the result. Review prose and a
positive label cannot bypass these checks. In particular, neither baseline
controller lookup under `109.4` nor unconditional new-object behavior under
`400.7` is permitted.
