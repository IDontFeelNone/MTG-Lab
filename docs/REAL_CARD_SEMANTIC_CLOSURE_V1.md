## Independent requirements and authority levels

`semantic_closure_policy.evaluate(requirements, premises, evidence)` is a pure,
bounded deterministic requirement evaluator. It contains no Card names, IDs,
text parser or gameplay controller. Requirements identify their dimension,
question, rationale, needed evidence, premise key, required authority level and
dependencies. Premises identify their state, authority level and bound evidence
references. Caller inputs are decoded into privately owned data before evaluation.

The real adapter supplies these premises only from admitted public evidence.
The pure evaluator is not an alternative admission API. A synthetic caller can
describe hypothetical established premises, but its output expressly says
`PURE_REQUIREMENT_EVALUATION_NOT_EVIDENCE_ADMISSION` and always retains execution
authority `BLOCKED`. A graph in which every requirement is satisfied grants no
review, permission, real profile or gameplay authority.

Authority levels distinguish validated identity bindings, retained source,
bounded reviewed source, owner-accepted interpretation, reviewed real procedure,
permission and execution authorization. Mere source presence cannot satisfy a
requirement for a reviewed real procedure. Evidence references identify admitted
container documents and exact JSON pointers; selected rule/projection/package,
span and review identities are supplied separately. Older inline source anchors
retain their original span/byte bindings without invented standalone anchor IDs.

| Status | Meaning |
|---|---|
| SATISFIED | This narrow requirement has established evidence at its required level. |
| MISSING | Required evidence or completed real-procedure support is absent from this admitted assessment scope. |
| UNKNOWN | Freshness, truth, applicability or sufficient authority is unestablished. |
| UNSUPPORTED | A condition is outside the supported interpretation/procedure scope. |
| BLOCKED | Explicit authority restriction, contradictory premises or a blocked dependency prevents stronger use. |

For dependency propagation the precedence is BLOCKED, UNSUPPORTED, MISSING,
UNKNOWN, SATISFIED. Every row retains its independent `local_status`, final
`status`, reason and unresolved dependencies. Rows in unrelated dimensions do
not inherit each other's status. Missing premises are MISSING; contradictory
premises are BLOCKED; duplicate/cyclic/malformed graphs reject. The report uses
no completeness percentage, confidence score or ready-for-execution boolean.

## Contracts and public usage

New domains are `real-card-semantic-closure-policy-v1`,
`real-card-semantic-closure-requirement-v1`,
`semantic-closure-requirement-graph-v1`,
`real-card-semantic-closure-input-v1` and
`real-card-semantic-closure-report-v1`. They reuse the existing domain/content
SHA-256 identity and canonical UTF-8 JSON codec. Policy, graph, individual
requirements, exact input and report have distinct deterministic identities.
Canonical files end in LF; the LF is not part of the domain/content identity.

The report's closed fields comprise schema/input/policy, selected identity and
dossier, historical text/freshness, accepted semantics, original capability
calculations, retained rule/review/frontier references, evaluated requirements,
separate status groups, evidence pointers, disposition/admissibility/authority,
integrity-checked detailed routes and limitations. Report validation recomputes
the entire expected report; a correctly rehashed substitute does not pass.

```python
from card_intelligence.semantic_closure import load_semantic_closure

# Supply the same independently expected roots/identities as load_land_overlay.
consumer = load_semantic_closure(**overlay_arguments)
report = consumer.assess('magic:legacy-promoted:card',
    '46a07b53-ff58-4bd6-80dd-ded2eb0e29a3', 'snow-wastes-mana')
consumer.validate_report(report.to_dict())
detail = consumer.detailed(report.to_dict()['detailed_references']['historical'])
```

The standalone read-only CLI is `python -B -m card_intelligence.semantic_closure`.
Use the existing overlay root/expected-identity options and then:

```text
--json assess --namespace magic:legacy-promoted:card \
  --card-id 46a07b53-ff58-4bd6-80dd-ded2eb0e29a3 --subject-id snow-wastes-mana
check
validate /path/to/report.json
detail /path/to/exact-reference.json
```

`--json` precedes the command. Exit 0 means successful assessment, never readiness
or approval; rejected evidence/input returns 2 with a structured error. No output
files are written. Readable mode lists requirements/rationales and evidence keys;
it never appends historical aggregate JSON. Explicit detail follows the existing
integrity-checked route. Returned documents are independent decoded views.
`check()` checks the admitted snapshot; another public load revalidates current
evidence. Original evidence changing after admission cannot retarget owned bytes.

The existing 65,536-byte canonical report and 32,768-byte readable bounds are not
increased. Pure-policy inputs have at most 64 requirements, 64 premises and 64
evidence references within 65,536 bytes; depth/types/duplicate-key limits reuse
the owning codec. Final actual sizes/timings and policy/input/report IDs are
recorded in the draft PR, together with local and hosted receipts.
