## Source-anchor convention

Every anchor identifies the exact physical line of the selected reference in the
original verified TXT. The span includes the rule marker and that line's source
bytes, excludes its line terminator, and includes neither subordinate rule lines
nor examples on other lines. The convention is recorded as
`EXACT_RULE_LINE_EXCLUDING_LINE_TERMINATOR`.

- `byte_start` is a zero-based inclusive offset into the original artifact.
- `byte_end` is a zero-based exclusive offset into the original artifact.
- `line_number` is one-based in the original physical line sequence.
- `span_sha256` hashes exactly those original bytes, before any normalization.
- `artifact_hash` binds every span to the required complete source identity.

Anchors must be nonempty, ordered, nonoverlapping and within the verified byte
length. A release-specific locator scans only for the exact allowlisted markers
and rejects missing or duplicate selected lines. It does not extract or build an
inventory of other numbered rules and is not a general/full Comprehensive Rules
parser. Source-aware verification recomputes all twenty anchors from the supplied
external bytes and reproduces the complete projection identity.
